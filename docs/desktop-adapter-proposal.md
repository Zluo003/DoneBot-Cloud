# 每用户专属 Cloud 桌面

用户已明确将本轮范围收窄为自有 Cloud 图形桌面替换 Boat，包含从本地工作空间访问云桌面所必需的创建、启停、查看、工具访问及文件回传，保留既有会话和工具语义，不同步团队或迁移任务。本轮据此修改 DoneBot 桌面入口、查看代理及附件交付调用点；不修改模型能力、媒体规划、原版收费或企业功能。授权不扩展到其他原版运行功能。

## 接口与生命周期

复用 `DoneBot/server/container-computer.ts` 的固定基础镜像、CUA driver 0.37.0 和镜像生成函数。Cloud 不复制原版运行源码；`scripts/desktop-dockerfile.mjs` 在临时环境中导出相邻 DoneBot 的 Dockerfile，构建仍使用其已校验的基础镜像、wheel 和字体摘要。

DoneBot 容器仅获得 `/run/donebot/cloud-desktop.sock`：每实例一个 UID 1001、0600 socket，监听器的闭包决定归属。它只接受固定生命周期动作、状态、截图、限时命令、文件下载和原生 MCP/查看字节流，不接受其他实例 ID、镜像、挂载、Docker 参数或宿主 shell。已有本地模式继续走原有实现。

每账户一个专属桌面，在本账户 Bot 间沿用 shared Local VM 语义；per-bot/pool 被明确拒绝，设置页禁用相应模式及节点管理的空闲参数。首次使用按需创建，默认空闲 30 分钟停止；查看连接或 MCP 会话存续期间保持运行。停止保留资料，删除桌面运行容器也保留资料盘。固定主机名仅映射到容器回环，确保完全禁网时 VNC 仍可启动。订阅停机或运行租约失效会拒绝新访问、断开连接并尝试停止桌面；实际停止仍受 Docker 响应时间影响。

本地 Bot 的引擎和会话仍在本机，使用云桌面时本机须保持运行；Cloud 工作空间中的 Bot 可独立运行。桌面控制在本地 Bot、Cloud Bot 和交互查看者之间互斥，丢失在途响应会保留待核对状态，不自动重复副作用。DoneBot 沿用原有 Computer API、完整截图校验、CUA MCP 工具及 who-is-driving 控制门。桌面文件经 100 MiB 上限的流式通道进入临时私有目录，再交给原有附件类型、大小、会话存续检查和私有存储；临时副本随后删除。下载仅允许桌面 workspace 内的普通文件，不提供宿主任意路径读取。

## 资源与数据

每桌面独立网络和固定容量 ext4 资料盘，新实例默认 10 GiB；`/home/cua` 整体持久化，包含 workspace、浏览器资料及用户安装的应用。运行服务数据盘默认 5 GiB，两盘合计硬上限 15 GiB，已登记较小磁盘保留实际容量。桌面限制为 1 CPU、2 GiB 内存/交换总额、512 PID、512 MiB shm，根文件系统只读，无发布端口、Docker socket、主控密钥或网关凭据。

桌面复用受控出网规则，使用另一张专属 nft 表和 bridge；不与本用户运行服务或其他用户共用网络。root supervisor 仅负责桌面启动，CUA、交互命令和查看桥均以 UID 1000 执行，no-new-privileges 禁止通过 setuid 获得新权限。宿主管理员仍受信，容器共享内核。

备份同时保存运行盘和桌面资料盘，作为一个用户可见快照。两盘全部解密认证和校验完成后才写入持久提交意图并替换；中途退出时，下次实例启动先完成提交。损坏任一备份都不覆盖原盘。自动轮换、到期回收和定向删除覆盖两盘及备份。备份后仅重新启动运行服务，桌面在下一次使用时启动。

## 验证范围

真实 Debian 13 ARM64 VM、两个 DoneBot 容器及两个桌面已验证：原生状态和截图、原 MCP 桥的工具调用、文件下载、独立 UID/卷/socket、原生查看 WebSocket、停机及租约失效断连、空闲恢复、双盘备份/损坏拒绝/幂等恢复、提交中断恢复、显式桌面镜像替换和定向回收。详见 [桌面验证记录](verification.md)。

打包 Electron GUI、完整真实模型驱动的聊天附件交付、目标服务器容量和安全对抗审计仍未验收。Linux 结果不表示控制了用户本机桌面或调用了真实余额；测试内容均为合成数据。
