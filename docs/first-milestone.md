# 首阶段：两用户独立云实例闭环

本阶段已扩展为 donebot-api 主控加多台 worker，账户、月付余额扣款和管理后台归网关。已实现并通过下列隔离 fixture 验证；真实 Linux 容器基础边界检查已通过，完整生产验收尚未完成。

## 已实现并验证

- [x] 核对真实接口、源码基线及修改授权，见 [接口核对](interface-audit.md)。DoneBot 的修改涵盖前端、统一网关接入、隔离验证工具及本会话明确授权的 Cloud 桌面适配。
- [x] Node.js 24 可运行工程、依赖锁文件、合成开发入口和隔离验证脚本。
- [x] PostgreSQL 持久化实例归属、订阅、节点容量、期望/实际状态、幂等操作及租约。节点不持有数据库凭据。
- [x] 使用网关认证主体确定用户 ID；浏览器正文、URL、转发头不能指定归属。节点身份、用户 JWT 和安装凭据分离。
- [x] 月付预付、条件余额扣款、同事务账单、并发一次扣费、余额不足不开通/续期、未激活取消或最终回收只退款一次。
- [x] 现有 donebot-api 后台配置月费、默认 7 天保留期、节点容量/地址，查看实例及扣退费记录。
- [x] HTTP / WebSocket 归属校验、节点短期签名、到期关闭连接/撤销运行租约；worker 停止续租时 agent 也尝试停机。
- [x] 停机保留数据；保留期后确认并锁定删除，失败可见且重试，不影响另一用户数据，保留账单历史。
- [x] 两个 Node worker 与真实 PostgreSQL 主控，按容量分配不同节点，worker 重启后回到原节点；错误节点及过期命令回报被拒绝。
- [x] 两个真实 DoneBot fake-engine 服务：原生配对鉴权、聊天/文件/记忆/配置、HTTP 归属和启停/控制器重启后的持久化；WS 归属由多节点合成运行时验证。
- [x] 网关 `/cloud` 用户页面：复用登录与余额、显示精确月费和保留期、收费/停机/取消确认、失败幂等重试、打开实例和撤销网页会话；组件与路由测试通过。
- [x] 真实 Chrome 联合流程：网关登录/开通确认、双节点两用户独立聊天、付费期内停启不重复收费、到期余额不足停机拒绝访问、补足余额后同实例恢复聊天、超期删除且另一用户不受影响。余额不足及容量不足页面明确失败并可重试；真实 JWT/处理器与私有 PostgreSQL，余额和模型为合成数据，见 [控制台证据](verification/console-2026-11-12.json)。
- [x] 每实例独立网页 origin，60 秒一次性开门码、HttpOnly Cookie、原生浏览器 WebSocket/SSE 授权、跨用户及跨 Origin 拒绝、撤销/到期断连；真实 PostgreSQL + 两 worker 验证通过。
- [x] 真实 Chrome 打开两个 DoneBot fixture，甲的消息不出现在乙；开门码从地址栏清除，页面脚本读不到 Cookie、没有网关 JWT；撤销甲后显示自有 Cloud 控制台入口。
- [x] 网关自动为已分配实例交付本用户安装凭据，节点校验归属后接入 DoneBot；真实 DoneBot 进程配合合成网关验证免二次登录、独立安装、模型请求与凭据不出现在公开状态中。当前 key 撤销/轮换后拒绝返回旧凭据。
- [x] 网关生成一次性 `donebot://pair` 链接，复用客户端原有探测、配对页和 Cookie 协议；原生协议与重放/IP/UA 约束通过集成验证。打包 GUI 未验收。
- [x] 后台节点令牌轮换/撤销、旧令牌立即拒绝、撤销暂停分配；worker/agent readiness 和 systemd 检查 timer。外部告警平台尚未接入。

## 真实 Linux 验证

- [x] 从核对过的 DoneBot 提交构建 `server` 镜像，按固定 image ID 创建两个真实容器，验证独立卷/IPC 目录、UID/CPU/内存/PID 配置、只读根、禁特权及网络隔离。
- [x] 一次性 Debian 13 ARM64：不同网络 namespace、另一用户卷路径不可见、无 Docker socket/控制密钥、网络拒绝、停启持久化及定向删除通过。这是基础检查，不是完整安全对抗验收。
- [x] `public-web` 受控出口：两个真实容器可访问公网 HTTPS/DNS 和网关匿名接口；独立 bridge + nftables 拒绝租户互访、宿主机私网/公网地址、元数据、非允许 TCP/UDP、IPv6、映射 IPv4 和 DNS 重绑定目标。防火墙缺失不开资源、失败原子更新保留规则、agent 重建和定向网络删除通过。
- [x] 新镜像自动读取 Cloud 安装凭据，两个容器身份分离；socket 固定 inode 并禁用连接池，用户替换 socket 为宿主服务链接后拒绝访问，原有固定连接不跳转，另一用户不受影响。
- [x] 固定容量 ext4（生产默认 5 GiB）；真实 ENOSPC、空间释放、另一用户可写、格式化中断恢复及定向删除。
- [x] Docker 创建中断、健康超时停机、agent 重建先停旧实例、卷忙导致删除失败后重试、加密备份/恢复/损坏拒绝及自动轮换。
- [x] 真正停止/启动专属 Linux VM，boot ID 改变；容器不自动重启，重新挂载后两用户持久化数据分离，定向回收通过。fixture 持久状态位于 `/var/tmp`，生产位于 `/var/lib`。
- [x] 原生 Browser SSE、画面帧、HTTPS 导航、两用户独立 Chrome 资料和 localStorage 停启保留；使用离线合成 Bot，无真实模型调用。
- [x] systemd 启动与宿主挂载可见性、agent 强制退出后 ExecStopPost 停机、agent/维护互斥锁；显式停机升级镜像并保留数据卷。

原 Ubuntu 下载源 DNS 失败后，改用 Debian 官方 ARM64 云镜像，校验 Lima 模板内的 SHA-512，已启动专用 VM 并通过 `verify:linux`。没有启动用户的 Docker Desktop、挂载用户主目录或连接生产数据。详细环境和结果见验证记录。
