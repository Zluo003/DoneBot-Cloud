# 首次发布与回退

当前交付是未发布的源码候选；三个仓库的工作区改动共同组成版本，单独记录 Git HEAD 不足以重建它。本文件不代表生产部署已执行。已有运行证据与仍未验收部分见 [阶段清单](first-milestone.md)。

## 固定候选版本

在 Cloud 仓库完成改动后执行：

```sh
candidate_dir=$(mktemp -d /tmp/dbc-release.XXXXXX)
node scripts/release-candidate.mjs "$candidate_dir"
node scripts/release-candidate.mjs --verify "$candidate_dir/manifest.json"
```

工具只读取三个仓库，在指定空目录写入 `manifest.json` 和三份源码归档。清单记录 HEAD（Cloud 尚无提交时为 null）、每个文件的 SHA-256、整个源码集合摘要、归档摘要及未提交文件列表；不提交、不推送、不发布镜像。只读取 Git 跟踪或未被忽略的源文件，拒绝环境凭据文件和仓库外链接；macOS 归档禁用 AppleDouble 附加元数据。输出不能在三个源码仓库内；源码在归档期间发生变化则失败，必须重新生成候选。配置、密钥、数据目录、依赖和构建缓存不属于源码归档。

验证命令同时检查当前源码和归档。源码变化后旧候选仍可保留作历史记录，但不能作为新源码的验收结果。`source-candidate` 不是正式版本号，也不等于镜像已通过生产配置验证；发布时需把候选的源码摘要关联到正式提交、构建日志和注册表摘要。

## 配套发布物

| 组件 | 构建与配套要求 |
| --- | --- |
| donebot-api 后端 | 候选网关源码、现有锁文件和正常构建链；包含 Cloud 迁移 260–263、主控与节点协议、浏览器会话和安装凭据服务 |
| donebot-api 前端 | 同一候选中的 Vue 前端；Cloud 页面与唯一管理后台随主控发布 |
| DoneBot 服务镜像 | 同一候选 DoneBot 源码的 `server` target；包含 Cloud 凭据、会话与桌面适配，使用正式完整引擎配置；隔离测试的 `ENGINES=` 不能直接作为生产引擎验收 |
| 专属桌面镜像 | 用同一 DoneBot 候选的原版生成函数导出 Dockerfile；按部署文档构建，保留 CUA/image-layer labels |
| Cloud 节点 | 候选 Cloud 源码及 `package-lock.json`，Node 24.13–24.x；agent、worker、maintenance 及 systemd 模板成套更新 |

发布到自有注册表后记录两个镜像的 `repository@sha256:…`、平台与构建配置。验证记录中的 `sha256:…` 是 Linux ARM64 测试 VM 的本地 image ID，不能填充为注册表摘要，也不证明 x86_64 兼容性。桌面 GUI 的签名安装包需另行验收；源码 renderer 与原生协议通过不能替代安装包验收。

## 发布顺序

1. 保全网关数据库、现有部署版本和主控签名 seed。已有 Cloud 节点还需保全完整 agent 状态、加密 key、磁盘及备份；这些材料由部署密钥和数据备份流程管理，不进入候选归档。恢复演练使用隔离副本。
2. 保持 Cloud 套餐关闭。按网关已有发布机制运行数据库迁移，再发布匹配的后端和前端。迁移 260、261、262、263 依序执行，不跳过正常迁移校验、不重写已应用迁移。核对 `donebot.enabled`、签名 seed、公钥和主控 origin。
3. 配置实例独立子域名、通配 DNS/TLS 和主控反向代理，核对 Host、Origin、WebSocket、SSE、禁止缓存及备份超时。实例域名指向主控；数据库只由主控私网访问。
4. 登记首台节点但暂停新分配。加载已审核的两个镜像，安装 agent/worker/health unit，写入私有环境配置与该节点专属 token。核对两类磁盘预算、私网 TLS、nftables、UID/GID、只读根与 Docker namespace。readiness 成功后再允许分配。
5. 在隔离预发布环境验收下面流程，再在后台确认月费和默认 7 天保留期后开放套餐。生产验收使用明确指定的新验收账户和预算；不能用已有用户或线上余额做自动化回归。

每加一个节点重复第 4 步，已有实例继续留在原节点。capacity 是名额，应由目标服务器实测决定；服务加桌面的资源上限不能被当成平均负载或超售依据。

## 开放前验收

通过真实控制台登录 → 查看余额和套餐 → 确认开通 → 核对一次扣费 → 打开实例 → 聊天、文件和桌面 → 停机/启动后资料保留 → 到期余额不足关闭访问和停机 → 保留期内补足余额后续费恢复 → 超过保留期删除。两用户并行时另一用户资料和会话必须保持独立。需要同时记录页面动作、接口结果、余额流水及资源结果；不能只截一张成功页面。

时间推进仅允许在本次隔离数据库中操作合成订阅，不能调整生产时钟或线上付费截止时间。付费至和保留期内续费的检查不需要真的等待一个月或 7 天；真实运行租约失效与实际容器停机另有 Linux fixture 证据。

## 回退边界

- **尚无 Cloud 扣费和实例时**：关闭套餐、暂停节点分配，停止本次新节点 worker/agent，确认它们的定向 fence 成功后回退前后端。260–263 是增量 schema，可保留；不要为回退旧应用自动 DROP 表或删除流水。若需恢复数据库，只能使用确认无新写入的备份并遵循网关已有恢复流程。
- **已有扣费或实例时**：关闭套餐会阻止新开通及自动续费，属于临时止损动作；先向运营明确影响，再暂停分配并停止相关 worker，确认 agent 租约失效与停机。保留主控数据库、实例卷、桌面盘、账单和密钥。优先修复并继续发布；没有经过隔离兼容验证的旧网关不能接管新订阅。禁止把数据库恢复到收费前的旧备份，否则可能丢失扣款和幂等记录。
- **节点镜像回退**：先停机并按 [部署说明](deployment.md) 执行受控升级准备。确认旧镜像可读当前数据 schema 后才切回；镜像回退不恢复数据。必要时从明确选定的成组加密快照恢复，两盘一起核对。不要删除状态目录或重建 deployment ID 来绕过规格检查。
- 回退或停机不等于取消收费成功。核对已激活/未激活的退款规则和每笔流水；不手工重复扣退费。所有资源失败保留可见错误，恢复后使用原幂等键核对未完成操作。

本轮没有执行生产迁移、发布、真实扣费、DNS/TLS 修改或用户实例操作。外部告警、异地灾备、目标机器容量、完整安全审计和打包客户端仍以阶段清单为准。
