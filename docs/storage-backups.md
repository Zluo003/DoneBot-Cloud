# 存储、备份与恢复

生产 agent 使用 `bounded-ext4`：运行盘及已配置的桌面资料盘各使用一个 root 私有、预分配的 ext4 镜像，经 loop 挂载后绑定到专属 Docker 卷。新实例运行盘默认 5 GiB、桌面资料盘默认 10 GiB，持久存储总上限 15 GiB，可用空间扣除文件系统开销。`CLOUD_STORAGE_BYTES` 与 `CLOUD_DESKTOP_STORAGE_BYTES` 均支持至少 128 MiB 的整数 MiB，两项配置总和超过 15 GiB 时拒绝启动。固定 inode 数量各 65536。硬配额覆盖 `/data` 内的聊天、文件、模型 CLI 状态及浏览器资料；`/tmp`、`/run` 另有内存 tmpfs 限额。

文件系统挂载使用 nodev/nosuid，校验 loop backing file、镜像属主/大小及卷配置。Docker local driver 不直接处理 `o=loop`。root agent 的挂载必须对宿主 Docker daemon 可见，因此 systemd agent 不使用独立 mount namespace。worker 仍使用服务沙箱，用户容器没有 mount 权限或 Docker socket。

已存在的普通 Docker 卷不会自动迁移为镜像。已登记的较小镜像盘继续使用持久记录的容量；提高新建默认值不会调整旧盘或备份大小，备份与恢复均使用实际容量。降低配置到小于旧盘容量时拒绝启动，不重建或格式化数据。既有磁盘的大小、属主、链接和 loop backing file 校验仍然保留。

## 用户操作

用户 Cloud 页在有效且运行中的实例上显示资源余量和备份入口。它们使用同一主控归属、订阅、签名及运行租约检查：

| 路径（实例代理内） | 行为 |
| --- | --- |
| `GET /api/cloud/resources` | 运行服务及桌面的 CPU/内存/PID、实际磁盘容量/可用空间/inode、合计资源与 15 GiB 上限、自动备份间隔 |
| `GET /api/cloud/backups` | 本实例备份列表和状态 |
| `POST /api/cloud/backups` | `{confirm:true,request_key:UUID}` 创建幂等备份 |
| `POST /api/cloud/backups/:id/restore` | 同样的确认和新幂等键，覆盖恢复 |
| `DELETE /api/cloud/backups/:id` | 删除本实例指定备份 |

创建和恢复会断开当前连接、停止运行服务和桌面并卸载文件系统，再执行操作；授权仍有效才重新启动运行服务，桌面保持按需启动。失败或响应丢失可用原 request_key 重试；恢复键绑定同一快照，不能更换目标。用户手动最多保留 3 份备份，删除后才可再创建。空间不足或损坏拒绝继续，错误不会标记清理成功。

## 加密与保留

备份是整个专属磁盘的 gzip + AES-256-GCM 快照；启用桌面时，一个用户可见快照同时引用运行盘和 `/home/cua` 资料盘，实例/快照/容量绑定为 AAD，root 0600 文件；密钥位于 agent 状态的 `backups/key`，与运行会话加密密钥分离。备份包含本用户保存的安装凭据、登录状态和文件，应按用户数据保护。恢复先对两盘完整认证并严格限制解压大小，再写入持久提交意图并分别原子替换；提交中断时，启动前完成剩余替换。不能把两个文件的替换称为文件系统级单次原子操作；恢复中的实例保持停机。任一认证失败都不覆盖当前盘。没有自动回滚应用 schema。

`CLOUD_BACKUP_INTERVAL_HOURS=0` 默认禁用自动备份；可设大于 0、不超过 720 小时且能换算为整数毫秒的值。agent 每分钟扫描，只处理仍有运行授权的实例，一次最多启动一个自动备份。创建第四份成功后删除最旧的备份，保留最新 3 份，手动备份也可能被轮换。失败保留状态，后续扫描重试。自动备份会短暂停机，停机实例不会因备份被唤醒。

镜像创建、备份和恢复均要求宿主额外空闲空间；单盘操作至少“该磁盘容量 + 512 MiB”，双盘恢复须为两份临时磁盘与压缩备份预留合计容量。备份轮换和恢复可能临时同时占用多份空间。节点 capacity 不能替代真实磁盘规划。

到期超过保留期并通过主控删除锁确认后，定向删除运行服务及桌面的容器、卷、磁盘、备份和本地凭据；另一用户不受影响。失败保留资源记录再重试。备份当前只在该节点本地，不能恢复整节点丢失；异地灾备还需单独实现。恢复节点必须一起保留 agent 元数据、deployment ID、密钥和备份，不应把单个加密文件视为完整灾备。

真实 Linux 证据见 [后续运行验证](verification/runtime-2026-11-12.json)，包括 ENOSPC、空间恢复、备份损坏、跨用户拒绝、提交中断恢复、轮换和删除失败重试。

桌面双盘恢复、损坏拒绝与提交中断证据见 [桌面说明](desktop-adapter-proposal.md) 和 [最新验证记录](verification.md)。原 runtime JSON 保留当时尚未接入桌面的历史状态。
